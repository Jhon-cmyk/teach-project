# 一、TCP协议概述

- **全称**：传输控制协议 (Transmission Control Protocol)
- **定位**：传输层核心协议之一
- **核心目标**：在不可靠的IP网络之上提供**可靠的、面向连接的、基于字节流**的端到端通信服务
- **典型应用**：Web (HTTP/HTTPS)、电子邮件 (SMTP/POP3)、文件传输 (FTP)、远程登录 (SSH)

---

<!-- _backgroundColor: linear-gradient(120deg, #d4fc79 0%, #96e6a1 100%) -->

# 二、核心特性

1.  **面向连接**：通信前需建立连接，通信后释放连接。
2.  **可靠交付**：无差错、不丢失、不重复、按序到达。
3.  **全双工通信**：连接双方可同时发送和接收数据。
4.  **面向字节流**：将应用层数据视为无结构的字节序列。
5.  **流量控制**：接收方控制发送方速率，防止接收缓冲区溢出。
6.  **拥塞控制**：感知网络拥塞，动态调整发送速率。

# 四、连接管理：三次握手

**目标**：同步双方的初始序列号 (ISN)，确认双方收发能力正常。

### 过程
1.  **SYN**：客户端发送 `SYN=1, seq=x`。
2.  **SYN-ACK**：服务器回复 `SYN=1, ACK=1, seq=y, ack=x+1`。
3.  **ACK**：客户端发送 `ACK=1, seq=x+1, ack=y+1`。

### 为何是三次？
- 两次无法防止**已失效的连接请求报文**突然到达，导致服务器资源被浪费。
- 三次是保证双方“发”和“收”能力都得到确认的**最小次数**。

# 四、连接管理：四次挥手

**目标**：双方优雅地关闭连接。

### 过程（假设客户端主动关闭）
1.  **FIN**：客户端发送 `FIN=1, seq=u`。
2.  **ACK**：服务器回复 `ACK=1, ack=u+1`。 (客户端 → 服务器方向关闭)
3.  **FIN**：服务器处理完数据后，发送 `FIN=1, seq=v`。
4.  **ACK**：客户端回复 `ACK=1, ack=v+1`。 (进入TIME_WAIT状态)

### TIME_WAIT状态 (2MSL)
- 确保最后一个ACK能到达服务器，并让本次连接的所有报文从网络中消失，防止新旧连接混淆。

# 五、可靠传输机制

### 1. 确认与重传 (ARQ)
- **停止等待ARQ**：每发一个报文，必须收到确认后再发下一个。效率低。
- **连续ARQ + 滑动窗口**：允许发送方连续发送多个报文，使用**累积确认**。

### 2. 超时重传 (RTO)
- 为每个已发送但未确认的报文段设置一个重传计时器。
- RTO值动态计算，基于RTT（往返时间）。

### 3. 快速重传
- 收到**三个重复的ACK**时，立即重传对方期望的报文段，而不必等待超时。

# 六、流量控制

**目的**：让发送方的发送速率不要太快，让接收方来得及接收。

### 实现机制：滑动窗口
- 接收方通过TCP首部的 **`窗口大小`** 字段告知发送方自己当前可用的接收缓存大小。
- 发送方的**发送窗口**不能超过接收方通告的窗口。
- **零窗口探测**：当接收方窗口为0时，发送方定期发送探测报文。

# 六、拥塞控制

**目的**：防止过多的数据注入网络，避免网络性能下降。

### 核心算法
1.  **慢开始**：窗口从1开始，每收到一个ACK，窗口大小翻倍（指数增长）。
2.  **拥塞避免**：窗口达到**慢开始门限 (ssthresh)** 后，每RTT窗口加1（线性增长）。
3.  **拥塞发生**：
    - **超时**：`ssthresh = cwnd/2`, `cwnd = 1`，重新进入慢开始。
    - **快重传/快恢复**：收到3个重复ACK，`ssthresh = cwnd/2`, `cwnd = ssthresh`，进入拥塞避免。

# 七、总结

- **TCP** 是互联网可靠数据传输的**中流砥柱**。
- 通过**面向连接、确认重传、滑动窗口、流量与拥塞控制**等一系列精巧机制，在不可靠的IP网络上构建了可靠的通信管道。
- **三次握手**建立连接，**四次挥手**释放连接。
- **拥塞控制**是TCP协议设计智慧的集中体现，对维持互联网整体稳定性至关重要。
