# 数据结构就业实战与面试指南

> 适用对象：以就业、项目开发、代码能力和面试为目标的学生。重点不是背诵定义，而是能说明为什么选择某个结构、如何实现、怎样验证边界条件。

## 1. 选择数据结构的工程原则

选择数据结构前先回答四个问题：数据规模多大、读写比例如何、是否需要保持顺序、是否存在并发访问。不要因为某个结构平均复杂度更低就无条件使用，还要考虑内存占用、缓存友好性、实现复杂度和业务约束。

## 2. 动态数组与链表

动态数组适合随机访问多、尾部追加多的场景，连续内存有利于 CPU 缓存。链表适合已经持有结点引用且需要频繁插入删除的场景，但对象和指针开销较大，实际遍历性能往往不如数组。

面试实现链表题时应统一使用虚拟头结点处理头结点删除，减少分支。快慢指针可用于寻找中点、判断环和定位环入口。反转链表要明确保存 next、修改指向、推进指针三步顺序。

## 3. 栈和队列的项目应用

- 浏览器前进后退可使用两个栈。
- 撤销/重做可使用命令栈，并为每个命令保存可逆操作。
- 消息队列和任务队列需要进一步考虑持久化、确认机制、重试、幂等和死信处理，不能只停留在内存 FIFO。
- 单调栈常用于下一个更大元素、柱状图最大矩形和温度等待天数。
- 单调队列可维护滑动窗口最大值，使整体复杂度达到 O(n)。

## 4. 哈希表

实现缓存、去重和索引时常使用哈希表。工程实现需要处理：

1. 合理的初始容量，减少频繁扩容。
2. 正确实现 equals 与 hashCode 约定，相等对象必须具有相同哈希值。
3. 冲突和装载因子。
4. 并发访问时不要把普通 HashMap 当作线程安全结构。
5. 缓存场景还需要淘汰策略、过期时间和一致性设计。

## 5. LRU 缓存

常见 O(1) LRU 方案使用“哈希表 + 双向链表”：哈希表负责快速定位结点，双向链表维护最近使用顺序。读取或更新后把结点移动到链表头；容量超限时删除链表尾结点，并同步从哈希表移除。

边界条件包括容量为 0、更新已有键、删除头尾结点、重复访问同一结点。Java 项目中也可以使用按访问顺序维护的 LinkedHashMap，但面试通常要求说明底层原理。

## 6. 树与索引

目录树、菜单树和组织架构常用树结构表示。数据库索引通常采用 B+树，原因包括树高低、磁盘访问次数少、叶结点有序且适合范围查询。不要简单回答“因为查找是 O(log n)”，还应说明外存块、扇出和范围扫描。

搜索建议和字典前缀匹配可以使用 Trie。若字符集很大或数据稀疏，需要避免为每个结点分配固定大小数组造成内存浪费，可改用映射或压缩 Trie。

## 7. 图在项目中的应用

- 依赖关系：拓扑排序检测循环依赖并安排构建顺序。
- 社交关系和关注推荐：图遍历、共同邻居和路径分析。
- 地图路径：根据边权条件选择 Dijkstra、A* 或其他算法。
- 服务调用链：使用有向图分析依赖和故障传播。

工程中图规模可能很大，应考虑邻接表、分页/分区存储和遍历深度限制，防止一次查询扩散到全部节点。

## 8. 并查集

并查集用于维护动态连通性。路径压缩和按秩/按大小合并结合后，操作的均摊复杂度非常接近常数。常见应用有好友圈、网络连通、冗余连接检测和 Kruskal 最小生成树。

## 9. 排序与 Top K

- 数据量小或基本有序时，插入排序实现简单且可能表现良好。
- 通用内存排序通常使用经过优化的快速排序、归并排序或混合算法，项目中优先使用标准库排序并提供正确比较器。
- 海量数据无法全部装入内存时，可使用外部归并排序。
- 从大量数据中取最大的 K 个元素，可维护大小为 K 的小根堆，复杂度约为 O(n log K)。
- 只需要第 K 大而不要求全部有序时，可以考虑快速选择，平均 O(n)。

## 10. 面试代码质量检查

1. 先确认输入为空、只有一个元素、重复元素、极端大小等边界。
2. 方法命名表达意图，不把所有逻辑堆在 main 中。
3. 明确修改了输入数据还是返回新结构。
4. 说明时间与空间复杂度，以及最坏情况。
5. 提供最少三类测试：正常路径、边界路径、异常或退化路径。
6. 涉及递归时评估栈深度；涉及共享状态时说明线程安全。

## 11. 推荐练习项目

### 项目一：可测试的 LRU 缓存

实现 get、put、容量限制、更新已有键，并编写单元测试覆盖容量 0、重复更新和连续淘汰。进阶要求增加命中率统计和并发安全版本。

### 项目二：任务依赖调度器

输入任务与依赖关系，使用拓扑排序给出执行顺序；存在环时输出具体错误。进阶要求实现并行可执行批次和失败依赖传播。

### 项目三：搜索建议服务

使用 Trie 或有序索引实现前缀搜索，支持新增词条、热度排序和 Top K。进阶要求考虑中文、拼音、缓存与数据持久化。
